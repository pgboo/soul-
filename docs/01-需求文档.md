## 2. 项目概述

### 2.1 一期定位
匿名/弱熟人身份 + 兴趣标签 + 灵魂测试 + 广场瞬间 + 匹配 + 内容社区与安全治理。

### 2.2 产品目标（3 个正交目标）
1. **能表达**：用户能快速建立弱熟人身份（资料 + 兴趣标签 + 灵魂类型），形成可展示的个人画像。
2. **能发现与互动**：用户能在广场发现内容、在匹配页发现人，并通过点赞/收藏/评论/打招呼/IM 单聊完成一次完整社交互动。
3. **能闭环**：所有主链路动作可追踪、可见结果、可通知（站内通知），为后续治理与运营留出接口位。

### 2.3 开发原则
- **不是 Demo**：所有功能要能正常运行、能闭环、能被后台管理、能被 OpenSpec 追踪。
- **协作流程**：需求确认 → UI确认 → OpenSpec确认 → 表结构确认 → 接口确认 → 后端开发 → 前端开发 → 联调验收 → 测试修复。
- **阶段门禁**：阶段 0–5 禁止编码，阶段 6–9 允许编码；**未完成前置阶段不允许编码**。

### 2.4 技术底座（硬约束）

| 类别 | 约束 |
|---|---|
| 后端 | Java Spring Boot 3 + MyBatis-Plus + MySQL 8.0 + JWT |
| 后台管理 | Vue3 |
| 用户端 | H5 网页（模拟小程序） |
| 依赖注入 | `@Resource` 字段注入；**禁止构造器注入** |
| 分层约定 | Controller 不接收/不返回 Entity，统一使用 Req / Resp / DTO |
| 表规范 | 业务表必须含 `id / create_time / update_time / is_delete` |
| 敏感信息 | 分表存 `user_sensitive_info`（手机号/openid）；主表与所有 Resp 均不返回 |
| IM | 统一使用既有 `im_conversation` / `im_message`，**禁止重造 chat 表** |
| 接口路径 | 前台 `/api/mini/*`，后台 `/api/admin/*` |
| AI | 对接阿里云百炼 DashScope（本期不实现，留接口位与兜底策略） |

### 2.5 一期规模基线
P0 需求条目 36 / UI 页面 23 / 数据库表 36 / API 接口 50 / 验收项 21（其中主链路 A001–A014 为本期验收）。

## 4. 用户角色与核心链路

### 4.1 用户角色定义

| 角色 | 定义 | 关键行为 |
|---|---|---|
| 访客 | 未登录用户 | 仅可访问登录页；未登录访问任何 `/api/mini/*` 受保护接口被拦截 |
| 新用户 | 已登录但 `profile_complete_flag=0` 或标签/测试未完成 | 进入初始化流程，逐项补全 |
| 老用户 | 资料/标签/灵魂测试均已完成的登录用户 | 登录后直达广场首页 |
| 被拉黑用户 | 被目标用户拉黑的用户 | 不可私信/打招呼/被推荐/评论对方内容 |
| 被禁言用户 | 后台禁言的用户 | 不可发动态/评论/消息/打招呼 |
| 被封禁用户 | 后台封禁的用户 | 无法登录及访问 |

### 4.2 主链路（新用户初始化 6 步）

```
① 登录页 输入手机号 → 获取验证码 → 提交登录
     POST /api/mini/auth/login  → 写 user / user_sensitive_info / user_login_log → 返回 token
                                    ↓
② 查询初始化状态  GET /api/mini/user/initStatus
     → 读 user.profile_complete_flag / tag_flag / test_flag
     → profile_complete_flag=0 → 进入资料初始化；=1 且均完成 → 直达广场
                                    ↓
③ 资料初始化页  填写头像/昵称/性别/生日/城市/签名 → 保存
     POST /api/mini/user/profile/complete → 写 user_profile，计算完整度 → profile_complete_flag=1
                                    ↓
④ 兴趣标签选择页  选 3–10 个标签 → 保存
     POST /api/mini/user/tag/save → 写 user_tag → tag_flag=1
                                    ↓
⑤ 灵魂测试答题页  8–12 道单选题 → 提交
     POST /api/mini/soulTest/submit → 计算 result_code → 写 user_soul_test_record → test_flag=1
                                    ↓
⑥ 灵魂测试结果页  展示灵魂类型/描述/社交建议 → 进入广场首页（广场首页）
```

### 4.3 主链路（老用户直达广场）

```
① 登录页 手机号登录 → POST /api/mini/auth/login
② GET /api/mini/user/initStatus → 三项均已完成 → 直接跳转广场首页
     （避免每次登录都走初始化流程）
```

### 4.4 关键交互链路（用户点哪个按钮 → 调哪个接口 → 改哪张表 → 出现什么结果）

| 用户动作 | 接口 | 写入表 | 结果 |
|---|---|---|---|
| 广场卡片点「赞」 | `POST /api/mini/dynamic/like` | `dynamic_like`、`dynamic_content`（计数+1）、`user_notice` | 按钮高亮，点赞数+1，作者收到通知（自己赞自己不通知） |
| 广场卡片点「收藏」 | `POST /api/mini/dynamic/collect` | `dynamic_collect`、`dynamic_content`（计数+1） | 收藏高亮，可在「我的收藏」看到 |
| 详情页发评论 | `POST /api/mini/dynamic/comment` | `dynamic_comment`、`dynamic_content`（评论数+1）、`user_notice` | 评论列表出现该评论，作者/被回复人收到通知 |
| 匹配页点「打招呼」 | `POST /api/mini/greet/send` | `greet_record`、`im_conversation`、`im_message`、`user_notice` | 对方消息列表出现会话，未读+1 |
| 聊天页发消息 | `POST /api/mini/im/message/send` | `im_message`、`im_conversation`（last_msg_preview/unread+1） | 对方会话预览更新，未读+1 |
| 进入会话 | `POST /api/mini/im/conversation/read` | `im_conversation`（unread=0）、`im_message`（read_flag=1） | 未读清零 |
